================================================================================
                         CHARGING SYSTEM OVERVIEW
================================================================================

TWO INDEPENDENT CHARGE SYSTEMS:

A. SHOP CUSTOMER CHARGING (EXISTING - SHOP_*)
   ┌─────────────────────────────────────────┐
   │ Shop Owner → Charges Customer → Shop    │
   │ Reference: SHOP_shopId_timestamp        │
   │ Amount: Variable (shop decides)         │
   │ Split Code: YES (routes to shop account)│
   │ Metadata: chargeType: "shop_charge"     │
   └─────────────────────────────────────────┘

B. PLATFORM REPORT CHARGING (NEW - REPORT_*)
   ┌──────────────────────────────────────────┐
   │ User Requests Report → Platform Charges  │
   │ → Platform Account                       │
   │ Reference: REPORT_PERIOD_shopId_timestamp│
   │ Amount: Fixed (50 weekly, 200 monthly)   │
   │ Split Code: NO (direct to platform)      │
   │ Metadata: chargeType: "report_charge"    │
   └──────────────────────────────────────────┘

BOTH WORK INDEPENDENTLY AND IN PARALLEL!

================================================================================
                         CHARGE TYPE IDENTIFICATION
================================================================================

WEBHOOK IDENTIFIES CHARGE TYPE BY:

1. REFERENCE PREFIX (Primary):
   ✓ REPORT_* → Report charge (Platform)
   ✓ SHOP_* → Customer charge (Shop)
   ✓ CYBER_* → Service charge (Agent)
   ✓ SUB_* → Subscription (Existing)
   ✓ INV_* → Invoice payment (Existing)

2. METADATA FIELD (Backup):
   {
     "metadata": {
       "chargeType": "report_charge" or "shop_charge"
     }
   }

If reference prefix doesn't match, webhook falls back to metadata field.

================================================================================
                         FIRESTORE COLLECTIONS
================================================================================

AUTOMATICALLY CREATED:

report_charges/
  {REPORT_WEEKLY_shop123_timestamp}/
    - reference
    - shopId
    - reportPeriod: "weekly" | "monthly"
    - dateRange: "last7days" | "last30days"
    - chargeAmount: 50 | 200
    - status: "pending" | "success" | "failed"
    - createdAt, updatedAt, paystackReference

shops/{shopId}/report_charges/
  {REPORT_WEEKLY_shop123_timestamp}/
    - (mirrored from above for shop-level queries)

platform_revenue/
  {REPORT_WEEKLY_shop123_timestamp}/
    - reference, shopId, reportPeriod, dateRange
    - chargeAmount, grossAmount, paystackFees
    - platformRevenue, status, type: "report_charge"
    - createdAt, paidAt

platform_stats/
  totals/
    - totalReportCharges: number
    - totalReportRevenue: amount
    - lastReportChargeDate: timestamp

================================================================================
                         USER FLOW (WEEKLY REPORT)
================================================================================

1. User selects "Weekly Report" → "Last 7 Days"

2. System checks: hasExistingReport(shopId, 'weekly', 'last7days')

3. IF NO EXISTING REPORT:
   ├─ System: "Enter M-Pesa phone for payment (KES 50)"
   ├─ State: REPORT_PAYMENT_PROMPT
   ├─ User enters: 0712345678
   ├─ System: initiateReportCharge() → STK push sent
   ├─ System: "Enter your M-Pesa PIN"
   ├─ State: REPORT_GENERATING
   ├─ User enters PIN in M-Pesa app
   └─ [WEBHOOK] charge.success received
      ├─ Updates: report_charges/{reference} status = success
      ├─ Records: platform_revenue/{reference}
      ├─ Generates: report automatically
      └─ Sends: WhatsApp success message

4. IF EXISTING REPORT:
   ├─ System: Generates report FREE (no charge)
   ├─ System: "Report ready - download link"
   └─ No Paystack interaction

================================================================================
                         WEBHOOK FLOW (REPORT CHARGE)
================================================================================

Webhook receives: charge.success

Reference check: REPORT_WEEKLY_shopId_timestamp

Type identification:
  ├─ Ref prefix: REPORT_ ✓
  └─ Charge type: report_charge

Processing:
  ├─ Update: report_charges/{reference}.status = success
  ├─ Update: shops/{shopId}/report_charges/{reference}
  ├─ Record: platform_revenue/{reference}
     └─ grossAmount, paystackFees, platformRevenue calculated
  ├─ Increment: platform_stats.totals
  └─ Send: WhatsApp success message (template provided)

Result:
  ├─ Platform revenue: KES 48.50 (50 - 1.50 fees)
  ├─ Proper tracking for accounting
  └─ User notified automatically

Recipient               Shop account         Platform account
Amount Type             Variable             Fixed (50/200)
Split Code              YES (shop)           NO
Reference Prefix        SHOP_*               REPORT_*
Menu Flow               Charge customer      Charge for access
Previous Access         N/A                  FREE (free)
Metadata Field          shop_charge          report_charge
Fund Routing            Split (shop % shop)  Direct (100%)
Accounting              Shop income          Platform revenue
