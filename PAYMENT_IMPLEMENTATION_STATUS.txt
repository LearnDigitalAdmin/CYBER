CRITICAL TECHNICAL DECISION:
  ✅ Using mobile_money endpoint (NOT USSD type)
  ✅ Using split_code parameter (NOT subaccount parameter)
  ✅ Reference format: SHOP_{shopId}_{timestamp}
  ✅ Phone format: +254XXXXXXXXX
  ✅ Payload matches user's proven chargeCustomer implementation

WHY THIS APPROACH:
  • Mobile_money endpoint is the correct Paystack endpoint for M-Pesa/Airtel
  • split_code parameter automatically routes funds through configured splits
  • Reference format with SHOP_ prefix enables easy webhook identification
  • Proven implementation (user's chargeCustomer function)

PAYLOAD STRUCTURE:
  {
    email: "stk-push-{shopId}@cogvana.co.ke",
    amount: amountInCents,
    currency: "KES",
    mobile_money: {
      phone: "+254XXXXXXXXX",
      provider: "mpesa" | "airtel"
    },
    reference: "SHOP_{shopId}_{timestamp}",
    split_code: "SPL_xxxx",  // Routes funds via split
    metadata: {
      shopId: "...",
      network: "safaricom" | "airtel",
      customerPhone: "...",
      type: "shop_charge"
    }
  }

================================================================================
                        ADMIN SETUP PROCEDURE
================================================================================

WHEN SHOP SUBMITS SETUP REQUEST (Option 6):
  1. Shop owner submits payment details via WhatsApp
  2. System sends WhatsApp to Cogvana (+254791286165)
  3. Message includes Shop ID for easy identification

ADMIN ACTION - Create Split Code:
  1. Go to Paystack Dashboard
  2. Settings → Subaccounts → Splits
  3. Click "Create Split"
  4. Configure:
     - Name: Shop_{shopId}_Split
     - Type: Percentage
     - Subaccounts:
       * Your Main Account: 97.5%
       * Shop's Account: 2.5%
  5. Save and get Split Code (format: SPL_xxxx)

ADMIN ACTION - Approve Setup:
  Call JavaScript function:
    const { approvePaymentSetupRequest } = require('./payment.setup.service');
    await approvePaymentSetupRequest('request_id', 'SPL_abc123xyz');

  This will:
    - Save to: shops/{shopId}.paymentAccount.paystackSplitCode
    - Mark request as "approved"
    - Shop can now charge customers

SHOP NOW CAN CHARGE (Option 7):
  - System reads shop.paymentAccount.paystackSplitCode
  - Sends STK push with split code
  - Funds routed via Paystack split configuration
  - Customer makes payment
  - Shop gets WhatsApp confirmation

YOUR EXISTING paystackCallback:
  - Should detect SHOP_ prefix in reference
  - Extract shopId from reference: reference.split('_')[1]
  - Call updateTransactionStatus() to update Firestore
  - Send WhatsApp confirmation to shop owner

HELPER FUNCTION PROVIDED:
  - findTransactionByReference(reference) - searches all shops
  - Returns: { found: true, shopId: "...", transaction: {...} }

WEBHOOK EXAMPLE:
  if (event.event === "charge.success") {
    const reference = event.data.reference;  // "SHOP_{shopId}_{timestamp}"

    if (reference.startsWith('SHOP_')) {
      const { found, shopId, transaction } = await findTransactionByReference(reference);

      if (found) {
        // Update transaction
        await updateTransactionStatus(shopId, transaction.id, 'success', event.data);

        // Send confirmation WhatsApp
        const shop = await db.collection('shops').doc(shopId).get();
        await sendWhatsAppMessage(
          formatPhoneForWhatsApp(shop.data().phone),
          `Payment received! Amount: KES ${event.data.amount / 100}`
        );
      }
    }
  }
