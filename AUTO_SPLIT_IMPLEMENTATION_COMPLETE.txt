================================================================================
                          COMMISSION STRUCTURE
================================================================================

Platform Commission: 1.5% (after Paystack fees)

Example: Customer pays KES 2,000
  ├─ Paystack fee: ~KES 39.80 (1.99%)
  ├─ Remaining: KES 1,960.20
  ├─ Platform (1.5%): KES 29.40 ✓
  └─ Shop (98.5%): KES 1,930.80 → to shop's subaccount

================================================================================
                          NEW ADMIN WORKFLOW
================================================================================

BEFORE (Manual):
  1. Shop owner submits payment details
  2. Admin manually creates split code in Paystack dashboard
  3. Admin approves with split code: approvePaymentSetupRequest(id, 'SPL_abc')
  4. Done

AFTER (Automatic):
  1. Shop owner submits payment details
  2. Admin gets shop's Paystack subaccount ID (from Paystack dashboard)
  3. Admin approves with subaccount: approvePaymentSetupRequest(id, 'ACCT_abc')
  4. First charge: Split code created automatically
  5. Subsequent charges: Cached split code used (instant)
  6. Done!

================================================================================
                          HOW IT WORKS
================================================================================

PAYMENT SETUP APPROVAL:
  Admin: approvePaymentSetupRequest('request_id', 'ACCT_abc123xyz')
    ↓
  System: savePaymentAccount() with paystackSubaccountId
    ↓
  Stored: shop.paymentAccount.paystackSubaccountId = "ACCT_abc123xyz"

FIRST CHARGE:
  Shop: Option 7 → Amount 2000 → Phone 0712345678 → Network Safaricom
    ↓
  System: getOrCreateSplitCodeWithRetry(shopId, 'ACCT_abc123xyz', 3, 1.5)
    ├─ Cache check: Not found
    ├─ Create: POST /split to Paystack API
    ├─ Paystack returns: "SPL_xyz789abc"
    ├─ Cache: splitCodes/{shopId} = {splitCode, subaccountId, ...}
    └─ Return: "SPL_xyz789abc"
    ↓
  STK Push: sendStkPush(..., "SPL_xyz789abc")
    ├─ Paystack receives split code
    ├─ Applies split automatically
    └─ Shop receives 98.5%, platform gets 1.5%

SUBSEQUENT CHARGES:
  Shop: Option 7 → Amount 5000 → Phone 0712345678 → Network Safaricom
    ↓
  System: getOrCreateSplitCodeWithRetry(shopId, 'ACCT_abc123xyz', 3, 1.5)
    ├─ Cache check: Found!
    ├─ Validate: ✓ Still valid in Paystack
    └─ Return: "SPL_xyz789abc" (instant)
    ↓
  STK Push: sendStkPush(..., "SPL_xyz789abc") (same split code)

================================================================================
                          RETRY LOGIC
================================================================================

If Paystack API fails:

  Attempt 1: Immediate
    ├─ Success? → Use split code
    └─ Failure? → Wait 1 second, retry

  Attempt 2: After 1 second
    ├─ Success? → Use split code
    └─ Failure? → Wait 2 seconds, retry

  Attempt 3: After 2 seconds
    ├─ Success? → Use split code
    └─ Failure? → Wait 4 seconds, retry

  Attempt 4: After 4 seconds
    ├─ Success? → Use split code
    └─ Failure? → Return error to user

Max total wait: ~7 seconds
Max attempts: 3 retries (4 total attempts)

User sees: "Failed to prepare payment routing. Please try again."
